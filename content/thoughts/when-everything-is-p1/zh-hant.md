回想以前還沒有 AI 時代。
在處理項目的時候，大家老是喜歡把 P1 掛上去，導致 Ticket 大多都是 P1 。
每個都是 P1 就沒有 P1 。

內部的系統疊代通常比想像中的慢，當時把 Ticket 排好，通常偏離的機率是 99％。
各種 P1 都會插入進來，倒是原本 P1 的變成了.....還是 P1 阿XD
後來演伸出了：上面說今天那個重要先做那個，明天那個重要先做那個，變成了很碎片化的開發。

說真的，我不覺得 AI 的程式有比人類寫的差，不如說，絕大多數人的程式品質，比現階段 Opus 5.5 的程式還爛，連個基本的 SOLID 跟 Pattern 都用不好。
追求 OOP 也弄得過多抽象，追求 ML 結果弄得亂七八糟的一堆。

因此你如果問我：AI 出來的 Code 你會擔心嗎？
我想反問：你那同事寫出來的 Code 你能放心嗎？

問題的本質是一樣的，不如依靠強大的 E2E 跟 AI 探測，來處理這個問題。
