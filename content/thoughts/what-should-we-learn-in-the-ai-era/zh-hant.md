我不覺得 AI 寫的程式有比人類寫的差。不如說，絕大多數人的程式品質，比現階段 Opus 5.5 寫的程式還爛，連基本的 SOLID 原則跟 Pattern 都用不好。

追求 OOP，結果弄得過多抽象。追求 ML，結果弄得亂七八糟的一堆。

所以如果你問我：AI 生成的 Code 你會擔心嗎？

我想反問你：你那同事寫出來的 Code，你能放心嗎？

問題的本質是一樣的。不如依靠強大的 E2E 跟 AI 探測，來處理這個問題。

至於學習跟自己寫程式，我認為這是對的，但這件事情已經變得有很高的門檻。

有點像糖一樣。工業糖越來越多，大家越來越愛吃，主動停止攝入糖分就變得很困難，尤其是那些吃越多糖的人。

現在大多數人都用 LLM 開發，而且一直專注在開發功能。他們的角色已經從工程師變成了 PM 或 Maker。

而坐下來自己寫程式，就像花很多時間鍛鍊肌肉。很痛苦，成長很慢，就算練得全身都是肌肉，也不一定代表薪水會更高。

很多人只在乎「功能」，缺乏對程式碼、架構和核心邏輯的理解，包括為什麼要抽象出一個 Pattern、為什麼要用 async、技術選型等等。

有經驗的工程師可能會寫出這樣的 Prompt：後端 Database 使用 SQLite，而且一定要使用 transaction。建立一個 class，在離開生命週期時自動 Commit，失敗時自動 rollback。建立的 connection 應該是長連線，使用 Pool 管理 session，並和我一起做 Database Table 的設計與正規化等等。

但一般沒經驗的新工程師或普通人：幫我把這個東西存起來。

沒有這些基本設計能力，描述又越來越高層次，你基本上對自己的專案和程式碼一無所知。之後面試時，你只能告訴我你做了什麼，卻沒辦法告訴我你是怎麼做的。

雖然工程師之間一直有個笑話，只要系統能動就好。一個 bug 是 bug，多個 Bugs 卻能運作。

現在的 LLM 開發確實就是這樣。

我也說不準未來會怎麼樣，或是這種設計能力還有沒有意義。

大多數不是軟體工程師的人，就算發布到 Prod，也只在乎能不能動。他們更在乎產品驅動，而不是技術。

如果連設計都已經是這樣，那再回頭自己手寫程式，體驗開發一個功能需要好幾個小時，一開始又只能寫出一堆亂七八糟的程式碼，成就感極低，這樣的時間投入根本就不划算。

我不知道現在和未來的新工程師或學生，還有多少人願意這樣做。

所以說真的，我們到底應該學什麼？

即使到現在，我還是沒有結論。AI 發展得太快了。很多技能正在變得沒有用，還讓人的思考僵化。同時又有很強的排斥和抗拒，你必須說服自己去看、去體驗、去掌握它。

就像繪師、譯者和軟體開發者，這些領域在前期都需要極高的投入，包括有限的時間和金錢。沉沒成本這麼高，又牽涉到個人的利益，該怎麼面對這種衝擊？我到現在還是很迷惘。

甚至到現在，我開始懷疑：人類到底需要學什麼？

最近我有個體會。我寫小說很久了，大概快 10 年。回想剛開始寫的時候，要把腦袋裡的想法轉成文字，真的像場災難。腦袋裡有很多想法，但要寫下來卻非常困難。

現在，我想到什麼就能把它轉成文字，並且一邊寫一邊改善。因此，我一直很難習慣語音輸入。

而最近我在學日文，依靠 LLM 幫助學習。直到昨天去考試，我沒想到竟然需要寫作文。

腦袋裡有想法，卻沒辦法把它轉成有效的書面文字。

有 LLM 幫忙，文字確實可以變得更乾淨，但基本上，我也失去了「構建思考與語言系統」的能力。

我回想起自己閱讀 LLM 給的文字架構時，當下覺得：就是這樣，沒錯。

但面對一張白紙時，我卻沒辦法自己構建出來，只能用類似「說話」的方式寫出內容。

所以現在我下定決心，至少在書面表達上，我需要自己寫，建立自己的語言系統與結構化輸出。

我真的沒想到，LLM 對學習造成的認知損害可以這麼強。

就像老師在黑板上講解數學，每一步看起來都很簡單、很合理。

但換成自己做時，完全是另一回事。

以我自己的經驗來看，很多人用 LLM 學程式，就像聽了一首鋼琴曲、看別人彈鋼琴，就覺得自己也會彈了。

未來很多人可能連自己進行結構化輸出的能力都沒有，包括基本的書面表達。

但如果說要回到以前傳統的學習方式，又覺得跟不上時代。

我沒有答案，但我個人會調整自己在吸收資訊後的「輸出」能力，以及結構化思考和進一步提問的能力。
