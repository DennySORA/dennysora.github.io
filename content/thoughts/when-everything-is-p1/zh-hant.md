回想以前還沒有 AI 時代。
在處理項目的時候，大家老是喜歡把 P1 掛上去，導致 Ticket 大多都是 P1 。
每個都是 P1 就沒有 P1 。

內部的系統疊代通常比想像中的慢，當時把 Ticket 排好，通常偏離的機率是 99％。
各種 P1 都會插入進來，倒是原本 P1 的變成了.....還是 P1 阿XD
後來演伸出了：上面說今天那個重要先做那個，明天那個重要先做那個，變成了很碎片化的開發。

我當軟體工程師也大約 5 年上下，成為了資深工程師。
我很幸運的是在 AI 到來時就已經是工程師了。
一直以來我都追求程式碼的簡潔、清晰，花了很多時間跟努力在程式重構上。
追求程式碼的品質與效率，開發出易擴充、高可用、低耦合的程式碼。
因此我在前 AI 時代，就一直再看那些優秀的開源程式碼。

但說真的，我不覺得現在 AI 寫出來的程式有比人類寫的差。
不如說，絕大多數人的程式品質，比現階段 Opus 5.5 的程式還爛，連個基本的 SOLID 跟 Pattern 都用不好。
追求 OOP 也弄得過多抽象，追求 ML 結果弄得亂七八糟的一堆。

因此你如果問我：AI 出來的 Code 你會擔心嗎？
我想反問：你那同事寫出來的 Code 你能放心嗎？

問題的本質是一樣的，不如依靠強大的 E2E 跟 AI 探測，來處理這個問題。

而且：學位 在軟體工程中屬於可有可無的東西（面試需要就是了），通常軟體工程屬於經驗工作，比起你知道更重要的是你能處理。
對於沒經驗真的蠻傷的，但工程師這個職位應該會越來越少，變成了需要大量有經驗的菁英職位就是了。
