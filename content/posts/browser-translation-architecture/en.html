The engineering core of this translation system turns a constantly changing webpage into work that is schedulable, reusable, and writable back after identity checks. The translation service produces the text; the extension makes sure the result appears in the right place at the right time.

Why account for service worker restarts?

Chrome's extension service worker is event-driven and may terminate while idle; ordinary JavaScript globals are not automatically saved. This project therefore writes translation memory and quotas to IndexedDB and lets pages redeclare active demands after reconnecting. This is lifecycle design, not a claim that the worker never stops.

02

Different entry points share different parts

Translation entry points share background resources and dispatch-approval mechanisms. Page batches, selected-text streams, and the Translation Center still retain their own output behavior.

Entry point How it enters the system Current presentation behavior
Webpage paragraphs Paragraph → sentence units → shared translation flow Wait for the final result, then update the screen only after confirming it still applies; no incremental temporary previews
Document title Independent text unit, assigned the priority of content near the visible area Manage only the top-level document; use request versions to prevent stale results from overwriting new titles
Subtitles Independent text unit, assigned the priority of visible content Return completed segments to the subtitle-rendering flow
Selected text · LLM Background text streaming; shared resource and quota approval Accumulated plain text can update the screen continuously, unlike page-batch response parsing
Translation Center Look up translation memory, then issue translation requests as needed Update cards after receiving the full response; use request identity to isolate cancellations and stale responses
Each entry point has its own retry strategy: Automatic service switching for page translation is off by default; selected-text translation also has an “LLM returns an empty string → try an enabled standard translator” fallback, plus up to 2 additional retries (waiting 800 / 1600ms).
03

First distinguish position, work, and requests

A page binding records a demand on the screen; shared work represents a reusable translation task; a request attempt is one operation against a particular translation resource.

How do two identical demands arriving together avoid duplicate sends?

The background scheduler indexes the “lookup in progress” work before the first asynchronous memory lookup. Later page demands subscribe to the same work; even if the earlier lookup has not returned, no identical task is created. This allows duplicate demands to merge even during asynchronous lookups.

04

Extract identifiable source text, not a bundle of HTML

Identify paragraphs first

Traverse using the DOM, display types, and exclusion rules, skipping the tool's own output, hidden content, and pronunciation annotations.

Then split into sentences

Use the browser's text-segmentation capability; above 2000 UTF-16 units, look for clause punctuation first, then grapheme boundaries.

Finally, retain identity

Each segment retains its original range, segment order, and source version; rebuild text units after the source changes.

Why must UTF-16, visible characters, and tokens stay distinct?

UTF-16 code units are the units used for JavaScript string length; an emoji may occupy several units, and multiple Unicode code points may form one visible character. A grapheme describes a grouping of these visible text units; tokens are determined by a model's tokenizer.

The default 2000 is the string-length limit per text unit. If a single grapheme exceeds it, the input is reported as too large. Without browser text-segmentation support, the fallback processes code points individually and cannot guarantee complete grouping of compound visible characters.

Short segments also use a local heuristic: after removing noise such as URLs, a single Latin-alphabet word may be skipped, while short segments containing Chinese, Japanese, or Korean text can be retained. This reduces fragmented requests but may miss meaningful words. Selected-text translation does not use the same short-text threshold as page translation.

05

Serve the current reading position first, then preload ahead

The page knows “where the source text is”; the background decides “which passage is worth translating now.” The preload region changes with reading direction and speed, while scheduling priorities are compared across pages.

Expand preload formulas and scrolling algorithm
Ahead range = min(10000, max(configured margin, round((multiplier + lead) × H))) Behind range = min(configured margin, round(0.5 × H)) Multiplier: not yet scrolled 1.5 / reading 3 / fast scanning 5 Lead: translation region 0 / paragraph-registration region 0.5

When the configured margin is ≤0, both sides return 0. Swap the upper and lower ranges when reading upward. Scroll speed is smoothed with an EMA: α=1−exp(−dt/200), new speed = old speed + (instantaneous speed − old speed) × α. dt is in ms, and instantaneous speed is in px/s; at intervals of 400ms or more, use the new sample directly.

A direction change requires accumulated reverse movement of max(120px, 0.35H). Forward speed of 2.5 viewport/s can trigger fast-scanning mode for 2 seconds. These thresholds reduce observation-region rebuilds caused by small backward movements; they are engineering heuristics, not a model of reading intent.

Read positions before updating the screen: The page first reads paragraph positions in a batch, then inserts placeholders. Later translation processing reuses position data supplied by the visibility observer, reducing interleaved layout reads and DOM writes.
06

Rules first decide what may be translated, then protect key terms

Rule precedence and Aho–Corasick's precise role

Handle whole-page disabling first, followed by whole-sentence keep-source / fixed translations, user-pinned translations, and no-external-send rules; only then replace phrases with placeholders. Banning external sending still permits locally saved translations to appear.

Aho–Corasick finds multiple phrases; “leftmost, longest” emerges from the subsequent sort and cursor-based selection together. Scanning uses UTF-16 code units and does not understand natural-language word boundaries. The full process also includes match expansion and sorting, so its total cost cannot simply be written as O(n).

Matching supports arbitrary text, exact whole sentences, and literal phrases, but not arbitrary regular expressions. If compilation or matching fails, the system can fall back to a more direct reference scanner.

07

Context must stay stable and obey the same external-send rules

Translation configurations with document context enabled freeze candidate text before the first batch is sent. The background then selects eligible content under the current policy, preventing “paragraphs forbidden from translation” from being sent indirectly as context for other sentences.

Which results can be reused after changing models or pages?

Page translation's semantic identity does not directly include the provider or model. With other semantic conditions unchanged, switching models can still hit an old result. Only “force retranslation” skips translation memory and the legacy cache, replacing memory under the same semantic key after successful result validation.

Selected-text translation and the Translation Center use their own entry-point contracts, and their translation configurations include the provider identifier. Thus, a provider A card in the Translation Center does not use a provider B card's results; changing the model within the same provider configuration preserves the existing identity.

Context, rules, and versions are also part of the semantic contract, with translations found by exact hash matching. Identical sentences on different pages can share results only when their other semantic conditions also match; merely similar text does not automatically hit.

09

Batching saves requests; dispatch approval protects resources and quotas

Candidate work is ordered by reading demand first, then an available translation resource is selected, and finally the system tries to form a batch. Larger batches combine more work; visible content uses smaller thresholds so the first results need not wait for too many sentences.

900 is not an absolute character limit per request: The first item enters the batch before total length is checked when appending others. A single sentence-split translation unit may exceed 900; prompts and context are not included in this source-text length either. UTF-16 code units, model tokens, and network bytes are three different measures.

Concurrency

Check the whole system, an individual translation resource, and all relevant quota groups together. Their initial default limits are 16, 12, and 16 concurrent slots, respectively.

Send rate

Each translation resource's token bucket replenishes capacity for 8 requests per second by default, accumulating at most 16. It controls the start cadence, not a guarantee of 8 completions per second.

Time-window quotas

Check requests per minute, tokens per minute, and requests per day according to configuration. Record additional usage when actual usage is higher; do not automatically refund reservations when it is lower or unreported.

Algorithm: when to wait for time, and when to wait for events?
D = S + P + a − L S = conservative debits committed to the time-window ledger that have not expired P = reservations whose send commit has not completed a = new demand L = configured limit
Condition Dispatch decision Meaning
a > L Block the demand This demand itself exceeds the limit; waiting cannot make it fit unless the configuration changes.
D ≤ 0 Pass this quota check Concurrency, send-rate, and other quota checks must still pass.
0 < D ≤ S Wait until a specified time Scan time buckets to find when enough debits will expire.
D > S Wait for a state change Even if all committed debits expire, pending reservations plus the new demand still exceed the limit.

For one translation resource, use the latest time threshold; if slots must also be released or writes completed, wait for those events. Across candidate work items, find the earliest possible wakeup time. Fixed-capacity circular time buckets prevent memory from growing without bound with historical requests: 62 buckets of 1 second for the minute window; 1442 buckets of 60 seconds for the daily window.

A debit's time-bucket index is ceil(attribution time ÷ bucket duration), rounded upward. When creating a persistence snapshot, the attribution time of pending debits is set at least 1000ms beyond now; after the transaction completes, ensure it is not before the current time, using conservative expiry. The request token bucket uses integer counts: one request equals 1,000,000 microunits. This is unrelated to the tokens into which models split text.

Algorithm: resource selection, token estimation, and optional adaptation

When multiple translation resources are available, first compare “compatible demand within the candidate window ÷ available concurrency,” using a denominator of at least 1. Then compare load, routing priority, and stable resource-identifier order. This heuristic selects among resources for the current candidates; it does not solve for a globally optimal allocation.

Estimate base = ceil(sum of all character weights) + 4 Character weight: 1 if the Unicode code point is greater than 0x2E80, otherwise 0.34 Full interactive prompt: ceil(sum of bases for all nonempty fragments × 1.2) + 256 Interactive output reservation: the request's specified limit, or 4096 if unspecified

This local estimate determines whether dispatch is allowed; it may differ from the provider's actual tokenization and cannot replace the account's remaining allowance. Page batches also include translation instructions and context in the estimate, so source character count alone cannot stand in for tokens-per-minute usage.

Adaptive concurrency is off by default. When enabled, the concurrency limit starts at half the hard limit, rounded up. When a successful response arrives and the statistics window has reached 20 seconds, check whether the previous window had at least 10 successes, pending work, and no congestion; only then add 1 slot. Capacity congestion halves the limit, at most once per adjustment cycle. Automatic fallback switching is also off by default and switches to other resources under eligible conditions only when explicitly enabled.

10

The model returns a data protocol; only validated output becomes a translation

Default page-batch translation maps each result using short identifiers. Output order may differ, but identifiers, translations, and placeholders must all pass validation. This separates “the entire response is invalid” from “only a few items need repair.”

Translation service Actual network behavior Response requirements
DeepSeek / OpenAI / Google Low-level automatic resending is disabled: each operation issues at most 1 network request, with retries managed by the upper-level scheduler. Custom service URLs must still satisfy the corresponding service's connection rules. Streamed text goes to the response parser and must conform to the structured data format.
Microsoft Within one operation, obtain Edge authentication first, then send the translation request; each phase is limited to 1 network request, for at most 2 total. Check the returned item count, restore the same item identifiers by original position, and convert to the unified format.
Which tolerances are allowed? Which numbers are not token limits?

The parser permits a leading reasoning section enclosed in designated markers, and Markdown fences that enclose the entire response and are unlabeled or labeled JSON. Valid whitespace and reordered data fields are accepted too. It does not guess and extract JSON from arbitrary prose. Large streaming increments are processed in chunks of 32,768 UTF-16 units, preserving text, escape, and Unicode parsing state across chunks.

Boundary Default value Measurement
Entire text response 262,144 2 × UTF-16 length, including envelope text
Network data volume of the model response 16 MiB Text-response budget × 64, including SSE and JSON envelopes
Per-item translation 24,000 UTF-16 code units

The product direction is “auto-detect source → Traditional Chinese for Taiwan.” Page translation and shared settings use different Traditional Chinese language tags; Microsoft additionally converts via an ISO language mapping table, falling back to a Traditional Chinese tag when no mapping is found. Integrations across services must handle these differences in language representation.

The system prompt asks the model to ignore instructions in the source and context, and to use plain text for translation content. This expresses the intended behavior but cannot guarantee elimination of prompt injection or translation errors. DeepSeek's thinking mode is off by default, and users may adjust it.

11

However quickly a result returns, first verify that the page is still the same

While translation runs, a dynamic webpage may change text, replace paragraphs, or navigate away, and the user may be selecting text. Background completion only means a candidate result is available; before actually updating webpage nodes, check the current source and interaction state.

Display mode How source text is handled How translations are written
Bilingual Keep source text in place; if an old translation exists, replace it only when the new update plan commits. Create nodes for the translation, then hand them to the rendering queue for updates.
Translation only Temporarily retain the original node objects, then remove them from the page; restore by reinserting those same nodes. The main path builds translations from text and line-break nodes; model text is not executed as HTML.
Finer rendering strategies: coalescing, deferral, and avoiding unnecessary rewrites

The rendering-cadence controller coalesces arriving results and adjusts cadence using recent work duration: new cost estimate = 0.6 × old cost estimate + 0.4 × current duration; next interval = min(1000ms, 2 × new cost estimate). A 250ms timer provides a fallback when the browser's animation-frame callback has not arrived. This tracks work duration, not the full cost of browser layout and painting.

Retain only the latest pending update plan per block, with at most 128 deferred plans. Beyond that, the system can record “refresh needed” markers, capped at 4096. Reconciliation after page changes coalesces into one in-progress job per paragraph plus one rerun-pending marker.

Rendering summaries use “text length + 32-bit FNV-1a hash” to decide whether rewriting can be skipped, unlike the background's SHA-256 semantic identity; different content can still have identical summaries. Multi-sentence translations are combined in original translation-unit order, with joins estimated from Chinese, Japanese, and Korean spacing rules rather than reproducing the original whitespace character for character.

Retaining the same original nodes helps preserve object relationships; event bindings, layout, and interaction behavior still depend on the website's own structure and update approach.

12

Being able to read a translation does not mean it is saved

How does the persistence queue bound memory?
Area Entry limit Estimated byte limit
Main persistence queue 32 16 MiB
Additional waiting area 64 8 MiB
Content retained after persistence failure 64 8 MiB

Waiting content and content retained after persistence failure have a 10-minute retention period, checked and cleaned up during later queue operations or retries. Capacity is estimated as “source UTF-8 bytes + translation UTF-8 bytes × 2 + 1024,” which may differ from actual memory use. When full, the queue pauses new page-translation dispatches; requests already sent may finish.

This queue exists only in runtime memory. When the background service ends, content whose write has not completed is not automatically restored on restart. 13

Cancellation revokes commit authority; retries need a clear reason

25 sWait for first content
20 sNo-new-content streaming deadline
90 sTimeout threshold per attempt
5 sGrace period to await termination after cancellation

These are adjustable defaults. The normal page-retry policy defaults to 4 actual sends, including the first, with a cumulative execution-time budget of 180 seconds. Oversized multi-item batches also have a repair path that splits them into individually requeued items. Demands never attempted and only waiting off-screen are exempt from the normal 30-minute demand expiry.

Failure Handling Why distinguish it?
HTTP 401 / ordinary 403 / 404 Treat as authentication, permission, or model-configuration problems; block the relevant translation resource. Blind retries will not fix configuration.
HTTP 429 · capacity-related Set a cooldown for the limited resource or quota scope; keep work queued until the resource becomes available again. Retry only after load drops.
HTTP 402 / 429 · billing or insufficient allowance No further retries by default; allowance-related 403 responses belong here too. Forwarding to another resource remains possible if fallback switching is explicitly enabled and an available resource satisfies the independent-fallback conditions. Billing / account-allowance problems are not transient congestion.
HTTP 408 / 409 / 425 / 5xx Treat as temporary server failures that may be retried. May recover over time, still subject to attempt and budget limits.
HTTP 413 / oversized input Split multi-item batches into individual retries; block the work if a single item remains too large. An oversized batch does not mean every item is untranslatable individually.
Retry timing, wakeups, and clock jumps

Delayed retries for ordinary work use full jitter: choose a random delay between zero and the upper wait bound each time. Capacity-related HTTP 429 instead sets a cooldown for the limited resource or quota scope, using the server-specified wait time, or the base delay if none is provided, without random jitter.

Wait upper bound = min(delay cap, base delay × 2^(attempt count−1)) Retry-eligible time = max(server-specified time, now + floor(random value × wait upper bound)) Random value is in [0, 1); floor means round down

Jitter spreads out retries; the response header Retry-After adds a lower time bound, accepting seconds or an HTTP date and accounting for server clock differences. Server-requested waits are retained for at most 7 days.

Wakeup scheduling is coalesced into one timer for the earliest deadline; when the expected wait is at least 30 seconds, a browser background alarm supplements it. Clock checks compare elapsed system time with elapsed monotonic time: a difference over 5 seconds, or a system-clock rollback over 5 seconds, pauses new dispatches. Conservative recovery occurs only after 2 stable seconds without another anomaly.

The cancellation diagram describes network attempts already sent. Attempts with reserved slots but not yet sent may end and release their slots first; if an ongoing debit transaction later commits successfully, that conservative debit remains even if the service was never called. Network operations whose termination cannot be confirmed quarantine the relevant resources and retain their slots until a late termination notice arrives. Restarting the background service establishes a new execution generation: old requests no longer occupy concurrency slots, but the known quota ledger is retained.

Reconnect the design to the problems it solves

Eight key boundaries for understanding this system

Streaming capability is separate from page displayThe lower layer can provide temporary previews; webpage paragraphs wait for final results. LLM translation of selected text updates using streamed text.
Resources are shared, but entry points still differDispatch approval is shared; response parsing, context, entry-point retries, and on-screen states differ.
Exact memory is separate from similarity searchA semantic key is the SHA-256 of the full translation conditions; similar text does not automatically hit.
Source-string length is separate from tokens2000, 900, and 2400 are UTF-16 thresholds at different stages; they must not be restated as token counts.
Concurrency slots are separate from quota debitsTermination can release a concurrency slot; consumption from sent requests remains in the time window.
4ms is a cooperative budgetOne indivisible update can exceed the budget, and the page can still drop frames.
Visible, saved, and synced are separateResult available, persisted, and sync complete are three independently advancing states.
Safeguards are separate from quality guaranteesPlain-text output and version checks reduce rendering risks; translation quality, cost, and performance still require separate measurement.
