# Project Agent Profile

## Product and quality profile

- Product: DennySORA's public personal site and technical blog, trilingual (Traditional Chinese, English, Japanese), prerendered to a static artifact and served by GitHub Pages at `https://dennysora.me`.
- Quality profile: `product`; use `release` evidence when publishing or changing the public domain, canonical URLs, routes, metadata or deployment behavior.
- This established public website overrides the generic local-application default. It is a static, responsive site for desktop and phone visitors, not a local desktop application: keep it static, with no first-party server runtime, accounts, forms, analytics or tracking. The owner-requested, automatically loaded giscus widget is the explicit exception for third-party comment forms and GitHub sign-in.
- Visual direction (owner, 2026-10-04): Moonlit Vim, a Neovim-style workbench in the semantic dark palette. Every page sits in a tabline of buffers, a neo-tree explorer, a winbar, a lualine-style status line and Vim's command line, and reads as a Markdown buffer with line numbers. The chrome is real links and controls, never a simulated terminal.
- Design system: [`docs/DESIGN.md`](docs/DESIGN.md) is binding for every UI addition or change (tokens, shell structure, typography, icons, generated illustrations and their acceptance, component recipes and the review checklist). Changing one of its rules needs owner approval and updates the document, tokens and guarding tests together.

## Owners and sources of truth

- Stack: React with React Router framework mode (prerendered, `ssr: false`), Vite, strict TypeScript, Tailwind CSS 4 (CSS-first), pnpm and Node. Versions live only in [`package.json`](package.json), [`pnpm-lock.yaml`](pnpm-lock.yaml) and [`.nvmrc`](.nvmrc).
- Routes: [`src/lib/route-manifest.ts`](src/lib/route-manifest.ts) is the single route contract; [`src/app/page.tsx`](src/app/page.tsx) loads each view and its metadata.
- Thoughts: `content/thoughts/<slug>/` stores independent original posts with three Markdown editions and simple metadata; `src/lib/thoughts.server.ts` owns its validation. It has no Blog source/revision/review fields, and covers are optional. Keep its empty landing page navigable. English must faithfully retain the original meaning and be the same text used for any later authorized Hacker News submission.
- Content: `content/posts/<id>/` (metadata plus per-locale Markdown), `content/profile/profile.json` (the home README résumé), `content/projects/`, `content/taxonomy/`. [`src/lib/content.server.ts`](src/lib/content.server.ts) and [`src/lib/schema.ts`](src/lib/schema.ts) load and validate them.
- UI: workbench chrome in `src/components/` (`TabLine`, `Explorer`, `WinBar`, `StatusLine`, composed by `SiteLayout`), pages in `src/features/`, strings for all three locales in [`src/i18n/index.ts`](src/i18n/index.ts), design tokens in [`src/styles/tokens.css`](src/styles/tokens.css), icons in [`src/components/Icon.tsx`](src/components/Icon.tsx).
- Build: `scripts/` validates content, finalizes the prerender (feeds, sitemap, legacy bridges, 404), builds the Pagefind index and checks the artifact.
- Data: `data/comments.json` (comment mode), `data/brand-assets.json` (brand asset provenance), `data/illustration-assets.json` (every shipped feature illustration with provenance and SHA-256), `data/article-covers.json` (published Note/Blog covers, localized alt text, responsive/social variants and provenance), `data/note-media.json` (note media streamed from Hugging Face), `data/post-media.json` (article videos, pinned commit, bytes, SHA-256 and subtitle contract), `data/post-sections.json` (article content tabs and localized labels), `data/migration/` (frozen anchors and migration maps).
- Documentation: [`README.md`](README.md) in English; [`docs/DESIGN.md`](docs/DESIGN.md), [`docs/CONTENT_WORKFLOW.md`](docs/CONTENT_WORKFLOW.md) and `docs/process/` in Traditional Chinese.

## Critical contracts

- Everything is published in all three locales: Traditional Chinese, English and Japanese (owner rule, 2026-10-12). Any change that adds or edits text ships its English and Japanese translations in the same change, covering UI strings, pages, notes, folder and Explorer names, metadata, alt text and generated labels. Never publish Chinese-only text, placeholders or untranslated fragments; text that cannot be translated yet is not published. Language links point only to published editions.
- The owner requested sitewide giscus with automatic comments and composer on 2026-10-25. It connects to giscus.app/GitHub automatically as its section approaches the viewport; reading needs no sign-in, while posting requires GitHub sign-in and may store a giscus session. Before that viewport-triggered load, the site makes no third-party resource requests and stores no interface state. All real localized pages share discussion identity across their translations; redirects and 404 pages do not embed comments. The owner also requested a minimal host UI: omit welcome/privacy boilerplate, duplicate empty/count messages and the host GitHub search link; keep the native giscus UI plus genuine loading/failure/retry states. The giscus widget requires JavaScript; the separate native-discussion mode keeps its direct link. AI/video content and local Paper Daily redirects were removed at the owner’s request on 2026-10-22; media registries are empty. The desktop Explorer and mobile drawer retain a localized external Paper Daily link, without a buffer tab, embedded content or third-party resource loading. Keep migrated routes, assets and metadata out of the static artifact. Generic media validation remains available, but no video is currently published.
- Unknown paths return a real 404.
- Brand images are the recorded repository files or their recorded derivatives, byte-checked against `data/brand-assets.json`; never recoloured, redrawn or filtered. Generated feature illustrations pass the transparency acceptance and are recorded in `data/illustration-assets.json` (DESIGN.md §7). Owner-requested Note/Blog covers are the opaque, no-text exception: one subject-specific image per published article, shared across locales, recorded separately in `data/article-covers.json` and served as responsive WebP plus a crawlable JPEG social image.
- Colour roles stay semantic: status colours only for real states, no opacity or filter dimming, WCAG 2.2 AA contrast.
- Pages remain readable and navigable without JavaScript, with keyboard access, visible focus and reduced motion.
- Public claims about the owner need repository evidence or explicit owner input.

## Validation and publication

`pnpm verify` is the pre-publication technical gate: Prettier, ESLint with zero warnings, type generation and `tsc`, Vitest, and the full build with content, search, route/SEO/feed and artifact checks. After deployment, verify the published HTTP responses and links.

Owner workflow decision (2026-10-25): the owner checks the live site's appearance and reports visual or interaction problems after publication. Automated browser previews, screenshots, Playwright/axe and paid rendering are not routine pre-publication blockers; keep them available as explicit diagnostic tools when requested or when investigating a reported defect. Record any unrun browser/visual checks honestly, never as passed. This changes the verification workflow only: it does not grant standing authority to commit, push, publish or change deployment permissions, and it does not apply to separate paper-publication workflows.

The owner commits directly on `main`; the `release` branch is the publication branch. This personal website is the owner's explicit exception to the general no-GitHub-CI policy: retain only the build-and-deploy workflow in [`.github/workflows/site.yml`](.github/workflows/site.yml). Every push to `release`, including a merge into it, builds and deploys that exact branch commit. Main pushes, pull requests, tags and manual dispatch do not trigger it. Run the repository's quality gates locally before creating or advancing `release`; the remote workflow installs locked dependencies, builds/checks the static artifact and deploys that same artifact with the existing Pages permissions and environment protection. Prefer a non-force fast-forward from verified `main`; inspect and resolve any branch divergence without overwriting history. Creating or advancing `release` is publication. Publishing, DNS or CNAME changes and GitHub Pages configuration remain external effects requiring an explicit request; this profile does not authorize them.
